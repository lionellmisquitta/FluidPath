When should I use—or avoid—this visual?

Use it for a mostly ordered journey where fewer requests normally remain at each step: recruitment, sales, onboarding, approvals, fulfilment or ecommerce.

Avoid it for parallel work, complex branching, recurring cycles, or a snapshot of how much work is currently sitting at each step. Those need a flow map, cycle visual or workload view instead.

A quick guide

How to use FluidPath

Turn a journey into a flowing story in seven short steps. Everything happens in this browser—your uploaded data is never sent anywhere.

  1. 01

    Watch the example

    Start with the living visual at the top. Switch between recruitment totals and request history to see how losses appear.

  2. 02

    Choose the description that matches your file

    Use Quick totals when you have one summarized value per stage. Use Request history when each row records a request reaching a stage.

  3. 03

    Add your data

    Upload an Excel or CSV file, paste rows, or try the working example. Download a template if you want a clean starting point.

  4. 04

    Confirm the columns

    For totals, FluidPath needs stage and reached. For request history, it needs request_id, stage and timestamp.

  5. 05

    Check the stage order

    Review the detected journey. Move, rename, remove or merge stages until the sequence tells the right story.

  6. 06

    Shape the presentation

    Choose colours, use a transparent background, add a title, and adjust loop, flow speed and the end pause.

  7. 07

    Export and share

    Save a still PNG for reports, a WebM video for playback, or an animated GIF for presentation decks.

Best fit: a mostly ordered journey where fewer requests normally remain at each step. Avoid this visual for parallel work, complex branching or recurring cycles.
